# Shot blocks: turn scene direction into controllable material

For short drama, distinguish the **edit shot**, whose boundaries serve action, reaction and
information, from the **generation block**, whose limits come from the endpoint. A block may supply
several shots, part of a shot, or nothing usable. Use the portion that works; a request's duration
does not entitle all its frames to enter the film.

Apply this installation's [RunningHub H3 constraint](runninghub-h3.md). Stronger inputs and sound
paths below are options only when that selected app actually supports them. If they are unavailable,
redesign within H3; do not add another video or generative lip-sync service as a fallback.

For faithful recreation, preserve the [detail requirements](story-transfer.md) when regrouping:
distinctive action phases, reaction close-ups, intensity and sound/effect timing are not expendable
handles. Splitting simplifies execution, not the required performance. Source negative/positive
directions must stay consistent across blocks.

## Resolve the composition before motion

For requested film/television quality, use [cinematic look](../creation/cinematic-look.md)'s accepted
integrated scene frames and actual static/motion checks. Send their useful photographic properties
through supported inputs and concrete H3 direction. A neutral portrait or ordinary composition
reference does not guarantee a photographic opening, and a great opening does not guarantee the
same material/focus/light quality through a turn or camera move.

Use [director planning](director-planning.md)'s boundary/instant test: a start image contains only
facts true at the accepted start, not the later payoff. An end image projects the authored end and
cannot invent a new result. Record reveal/text permission and camera purpose. Preserve shot IDs
independently from block/job IDs when regrouping or repairing.

Prepare and accept a key still when identity, scale, crowd, prop state or exact framing depends on
it. Combine accepted masters with current scene state. Simple inserts, supplied footage or already
accepted continuous performance need not acquire redundant keyframes. Where an exact opening
matters, bind the image through a supported first-frame operation. For precise endings, use last
frames only when compatible with the other required inputs. Reference generation is a different
control relationship.

If input slots are limited, a coherent composite can carry several visual facts in one image, with
selected identity references in remaining slots. Verify the faces and states in that composite and
the output. Do not discard a required control to fit the endpoint.
[Request controls](request-controls.md) owns modes, binding and submission checks.

## Direct legible action and camera geometry

For a consequential physical interaction, specify the necessary observable phases rather than an
action label: entry/support -> preparation or weight shift -> contact/manipulation -> the other
subject's consequence -> release/settling and exit state. Include only phases the action needs;
an action already underway need not restart. State which hand/foot, object surface and participant
carry each phase, including concurrent listener behavior. Use source timing/intensity for recreation
and the accepted world's physics for stylized work, without demanding restrained realistic acting.

For example, handing over a heavy case may require the giver's grip and supported stance, the
receiver grasping its handle before release, a small arm/shoulder response to the load, and the
giver's hand withdrawing. Encode these conditions only if observed/required; do not substitute
this example for the source's own action or invent weight for a light prop.

Keep contact-critical phases readable through camera angle, shot size, focus and duration. Give
motion its trigger, path, pace and landing when it matters. A still or first/last pair establishes
boundary states, not the intermediate handoff. The actual output must show it. If a split is needed,
preserve phase/state continuity and allocate action and reactions before submitting the blocks.

Derive eyelines from participant positions, relative height, gaze target and camera side; there is
no universal down-left/up-right pair. Project the same world-space light into each view. An axis
crossing or vigorous camera move may be deliberate when geography and attention remain legible;
fixed shots, shallow focus and an establish/over-shoulder/close-up sequence are not compulsory.

## Inherit the adopted editing state

Separate reference responsibilities in the input plan: identity/look, world/local state, performed
timing and expression, camera/rhythm, sound and atmosphere. A previous target tail usually establishes
local state; it does not prove the source's gait, reaction or interaction has been transferred. For
each critical temporal detail, state the actual carrier and remaining uncertainty. Inspect any
processed/masked reference through its useful interval: eyes, mouth, contact and timing must remain
legible if that input claims to carry them. When identity leakage or service restrictions prevent
using source footage, use a readable target-cast rehearsal, phase-specific assets and H3 direction;
trial the result rather than declare a destroyed reference sufficient.

Long-term identity and locations belong to accepted masters. Local state comes from the predecessor's
**adopted usable interval**: use the frame at its actual edit boundary or an appropriate excerpt,
not automatically the raw file's last frame. A drifting tail trimmed out of the film must not become
the next shot's starting state. Record candidate version and source time used for extraction.

Continue exact motion with frame or video continuation inputs when supported. For a reverse angle,
carry world state into the matching camera's accepted composition; repeating the predecessor's
literal framing would defeat the reverse shot. Independent scenes start from relevant masters and
their own established state. Time jumps inherit only persistent facts.

Use camera-matched views, current outfit and relevant expression coverage. Do not accumulate all
previous frames as references. Compare against masters as the chain develops; repair drift instead
of adopting it. Contradictory reference roles need exclusions or replacement before submission.

Dependent blocks wait for the parent's accepted candidate and selected boundary. Independent inserts
or branches with settled shared facts may generate in parallel. If an upstream candidate, cut point,
outfit or layout changes, mark affected descendants for recheck. Preserve outputs that still satisfy
the revised facts; do not regenerate unrelated material.

## Choose the sound and performance path

Keep useful H3 native sound as the default base; this does not require all sound to be made in post. Start from [sound direction](../creation/sound-direction.md): scene hearing perspective,
character tactics, cue/reveal timing, music and quiet. For newly produced visible dialogue,
prefer an actually supported voice-timbre reference with H3 jointly generated performance,
then preserve adopted native sound and finish the chosen score/cues in post. Exact-track
drive is selected only when its control is verified and the scene benefits from it. Native
text-directed speech remains a valid scoped trial path when audio reference is unavailable,
with voice continuity an explicit output uncertainty rather than a claimed technical lock.

Plan scene dialogue and listening rhythm before video, then choose the timing authority:

| Path | Timing authority | Execution and acceptance |
| --- | --- | --- |
| Exact dialogue track | Accepted scene recording/generated dialogue, split at meaningful beats | Verified exact-audio/performance-driven or lip-sync route; bind real excerpts and inspect visible speech against them |
| Jointly generated picture and speech | Adopted audiovisual performance | Scratch dialogue guides the beat; bind voice references where supported, measure the result and adapt the edit |
| Off-screen or covered speech | Accepted independent audio | Keep the chosen track in the edit; use appropriate listener/insert coverage and preserve speaker attribution |

A voice reference guides timbre and possibly delivery; it does not guarantee the waveform, word
duration or mouth movement. Audio reuse and exact speech drive are also distinct: copying sound does
not establish lip synchronization. Verify the operation and payload. If a stored schema lists audio inputs but the runner sends `None`, inspect/implement the
actual authorized new-production binding and test its duty before batch; that is an adapter
gap, not evidence the model lacks sound control. If no supported audio input exists,
record the gap and select a viable path within RunningHub H3; text-only voice descriptions are not a voice lock. Do not
replace visible generated speech with different dialogue merely because total durations are similar.

Map every speaker to their own voice and preserve interruptions and listener reactions. If the route
cannot drive multiple faces independently, use supported single-speaker coverage or a validated
composite workflow. Face-performance transfer alone does not solve body scale, contact, shared props
or crowd choreography.

Design music, ambience and effects across the scene. Silence, cue changes and different themes may
be motivated; there is no one-song requirement. Avoid independently generated scores per block.
Where supported, request clean dialogue without baked-in music and keep the final score separate.
Listen before adding layers: duplicated ambience or music also breaks continuity. J/L cuts can carry
complete speech across picture cuts; do not crossfade syllables to hide a visual problem.
[Sound and mix](../playbooks/craft/sound-mix.md) owns implementation choices.

## Preserve motivated light

The [style lock](../creation/style-lock.md) owns the production's photographic signature — base
layer, color cards, iron rules; this section owns their per-camera truth.

Establish palette, exposure relationships and physical light sources. Project world-space light into
each camera: a window may illuminate screen-left in one view and screen-right in the reverse. Do not
paste an identical screen-relative lighting suffix into every shot. Record changes such as switching
a lamp on or moving into shade. Match comparable surfaces before a shared final grade; a LUT cannot
repair inconsistent light geometry.

## Choose stronger control at the failing layer

Use [production calibration](production-calibration.md) to select disposition before changing the
prompt. A bounded pickup supplements its master; a candidate only replaces it after required detail
coverage is reassessed. Keep a change set and a preserve set so an unrelated good beat survives.

Within the agreed budget, choose a control that addresses the observed failure:

| Failure | Useful next control |
| --- | --- |
| Face or outfit | Correct master/version, view-specific reference, repaired key still |
| Scale, contacts, crowd or blocking | Composite/3D layout, simpler coverage, accepted camera views |
| Restraint or reaction timing | Recorded rehearsal/performance transfer; keep trigger and response in one supported block |
| Spoken timing or voice | Supported sound path, clean voice reference, speech-driven route or motivated coverage |
| Boundary cannot cut | Better usable interval; reframe action unit or use a motivated reaction/insert |

First/last frames and performance transfer are alternatives, not mandatory rungs for every shot.
Validate the difficult passage before scaling a changed configuration within the permitted route.
Permitted asset preparation and editing can supply material while Hypit owns scene and delivery.
Use [scene acceptance](scene-acceptance.md) to
judge whether the control worked.
