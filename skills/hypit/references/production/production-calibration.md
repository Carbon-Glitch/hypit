## Keep observations local to their evidence

An input inspection establishes what a reference contains; it does not demonstrate generated behavior.
An output observation identifies the prompt/shot version, ordered reference set and scopes, actual
app/configuration, media/version, source interval, viewing method and limitation. Separate observed
facts, likely causes, alternative explanations and the proposed change. A job success or thumbnail
cannot prove a performance or sound result. Do not promote one project's behavior into a universal
H3 rule without broader evidence.
Select evidence by the property under test. A silent material/look clip cannot calibrate acting,
partner rhythm or voice. When those matter, inspect a representative actual exchange and its
boundaries. Record which uncertainty each trial resolves and what remains untested; reuse valid
evidence instead of adding a fixed audition quota. Export actual adopted findings through
[acceptance evidence](acceptance-evidence.md) and feed them back into owning shot/cue/state records.

Select representative risks from this project: meaningful expression/register, full-body scale,
contact, relevant crowd behavior, speech load, readable surfaces, difficult light or boundary handoff.
No fixed test count is required. Reuse valid accepted evidence; new paid trials stay within the
existing agreed work and budget. Prior authorization remains authoritative.

## Pickups supplement; replacements need coverage proof

A master candidate supplies its full assigned requirements. A pickup supplies a bounded action,
reaction, effect or coverage element and normally coexists with it. An alternate candidate is a
proposed replacement whose adopted intervals must still cover all assigned details. For each repair,
record parent shot/block, precise start/end state, supplied detail IDs, details retained in the master
or other pickups, unresolved obligations and proposed editorial use.

Do not silently promote a short hand/face pickup into the new master while losing the dialogue,
listener, reveal or exit state. Keep unchanged shot IDs where responsibility is unchanged; use
explicit successor relationships for splits/merges. Update story allocation and the actual edit
against the chosen candidate. [Director planning](director-planning.md) owns these identity rules.

## Recover a submitted task before paying again

Save the provider task ID and exact request identity immediately after submission, before polling.
On interruption, inspect saved RunningHub status and recover/download that existing task when possible.
A missing observer or local file is not a failed remote job. Do not automatically resubmit a request
whose outcome is unknown. Retrieval is distinct from new generation; use only supported RunningHub
query/download operations, not invented CLI commands.

When retrying under an existing budget, record changed versus identical content, technical versus
content failure and expected benefit. Stop at the agreed cost/attempt boundaries. The upstream
workflow's per-attempt confirmation mechanism is not imported; Hypit's existing spending agreement
and the user's settled authority still govern execution.
