# Director execution contract: preserve control through H3 compilation

Read for complex action, fragile reveals/transitions or request diagnosis. Keep
decisions in existing Treatment, shot rows, asset scopes and sound/post records. This is a planning
vocabulary, not another mandatory JSON project or a replacement for official H3 prompt sections.
For whole-scene artistic execution first use the [director blueprint](../creation/director-blueprint.md).
It connects essential experience, tactics, attention, sound and cut to these carriers. The
[combined submission gate](production-gate.md) checks their reviewed request versions; actual
[acceptance evidence](acceptance-evidence.md) closes them against adopted media.

## Name the actual carrier of each important condition

Record condition -> authoritative version -> carrier -> actual H3 clause/input or post destination
-> observable acceptance condition. Several carriers may support one condition, but none may be
assumed active merely because a file exists. Choose only needed assets and modules.

| Carrier | What it can own | What still requires direction or evidence |
| --- | --- | --- |
| Text-directed execution | Action sequence, triggers, feedback, camera and sound timing | Feasible duration and observed performance |
| Accepted visual references | Identity/look, layout, boundary state, materials and palette within declared roles | Intermediate actions, emotion arc and supported temporal inputs |
| Existing-video change | Preserved source properties plus one declared change | Verified H3 edit operation; a normal video reference is not a preserve-all edit |
| Accepted dialogue/audio | Voice, words, timing or reused waveform according to the supported route | Visible synchronization and listener behavior; reference/reuse/drive are distinct |
| Post instruction | Designed overlay, color/effect or independent sound | Filmed prerequisites and actual rendered/heard result |

When compacting text, identify where each omitted condition survives. Static references cannot
replace action timing. Do not repeat an entire asset-generation brief in a motion request, but retain
enough identifying/state/lighting detail to meet the official H3 guide and avoid conflicting roles.
No control-source label activates a new RunningHub feature.

## Describe execution at its useful scale

For required local action, the useful unit is:

```text
time window + start state + action path + contact/physical feedback + end state
+ camera sync + audio sync
```

Use it where phases matter, without forcing every blink into seven fields or a numeric timecode.
Distinguish sequential prerequisites from simultaneous action. Leave time for the reaction and
editable landing; neither a fixed actions-per-second limit nor a mandatory hold duration applies.
Check each transition inherits the preceding state. [Shot blocks](shot-blocks.md) owns execution.

For a frozen action image, resolve body facing, visible/hidden anatomy, support/contact, prop state,
pose tension and visible traces of the ongoing/prior action. Cloth tension or displaced objects may
clarify causality when observed/required; do not invent aftermath or a future payoff in a start frame.
This augments [boundary planning](director-planning.md#freeze-one-declared-boundary), not a motion
timeline inside an image prompt. For embodied POV, resolve camera/eye height, connected limbs,
reach, support/platform and occlusion rather than floating hands in an unrelated third-person view.

## Resolve rules by phase and representation

Tag relevant constraints as global, local phase, final boundary or explicit scoped exception in the
owning shot rows. A fixed first phase followed by a triggered pan is not automatically a conflict.
A continuous-take requirement and an internal hard cut are contradictory unless the chosen design
explicitly changes. Keyword overlap routes review; read actual scope and cause before declaring a
blocker. A camera/framing exception cannot waive source fidelity or reveal permission on its own.

When crossing live space, memory, screen, mirror, stylized reaction or schematic map, state the
entry/exit trigger and what identity, props, time and spatial rules persist. Graphic arrows, board
labels, chibi scale or inverted gravity belong only to their assigned layer. A real mirror reflection
still needs geometry; calling it a separate layer does not excuse an inconsistent reflection.

If color carries information, record allowed objects, excluded objects, narrative meaning and when
that meaning changes. Palette swatches/labels do not belong in final footage. Shared colors cannot
automatically recolor skin/wardrobe or disclose a hidden prop. HEX values document intention, not
pixel guarantees. Reference assets used only as rejected examples remain review evidence and must
not be sent as positive generation references.

## Reverse-read the final request

Independently reconstruct the requested visible/audible sequence from final text and actually bound
media. Compare it with the original detail evidence and target shot contract, not the preceding
prompt draft. Inspect missing action feedback, absent listener coverage, unintended reveals, rule
conflicts, reference-duty leakage, ownerless controls and impossible duration. Mark uncertain H3
behavior as a trial risk rather than a proved capability or an automatic creative failure.

Keep the complete director decisions when a verified app limit requires shortening the compiled
prompt. Remove duty-free repetition first; relocate supported static control only with actual
binding/evidence, or restructure blocks without losing necessary action/reaction. Save what changed
and compare the final serialized version in the same adoption pass. No clipping, Seedance field names
or eleven-section template replaces H3's required mode structure.
